# NI-PML agent instructions

## Read before working

Read these files before planning or editing:

1. [`assignment.md`](assignment.md) for the course requirements.
2. [`topic.md`](topic.md) for current working notes.
3. [`docs/ai/PROJECT_CONTEXT.md`](docs/ai/PROJECT_CONTEXT.md) for stable project facts and constraints.
4. [`docs/ai/PROJECT_TODO.md`](docs/ai/PROJECT_TODO.md) for open decisions and planned work.
5. [`docs/ai/RESEARCH.md`](docs/ai/RESEARCH.md) when selecting papers, venues, datasets, or research directions.

The repository contains `assignment.md`, not `assessment.md`. Use `assignment.md` as the assessment brief.

## Keep the AI documentation current

After every meaningful edit, experiment, research decision, or change in project scope, update the relevant file in `docs/ai/` before handing off the work. Use the date, keep entries concise, and change only the files affected.

| File | Put this information here |
| --- | --- |
| `docs/ai/PROJECT_CONTEXT.md` | Stable assignment requirements, confirmed project facts, constraints, and working rules. |
| `docs/ai/PROJECT_TODO.md` | Open decisions, active tasks, confirmed decisions, and proposed next steps. |
| `docs/ai/RESEARCH.md` | Verified conference, paper, dataset, code, evaluation, and compute findings, with source links. |

When a base paper is selected, record its eligibility and rationale in `PROJECT_CONTEXT.md`, its follow-up work in `PROJECT_TODO.md`, and its sources or implementation findings in `RESEARCH.md`.

## Evidence-first rules

- Separate confirmed facts, proposals, assumptions, and open questions.
- Verify a paper's year, venue, and track before calling it an eligible base paper.
- Cite sources for claims about papers, code, datasets, licenses, metrics, and resource requirements.
- Preserve existing user edits.
- Keep experiments reproducible and within the confirmed resource budget.
